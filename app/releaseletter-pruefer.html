Eine fertige n8n-Workflow-Datei zum Import — gleiche Pipeline wie in Dify: Jira-Ticket → belegter Releaseletter (DE+EN) + Zusammenfassung, mit Guardrails und PII-Scrub. Der Workflow läuft komplett in eurem n8n.

Start → Eingabe → Extract & Prepare (Code) → LLM Releaseletter DE → LLM Übersetzung EN → LLM Zusammenfassung → Merge & PII-Scrub (Code) → Ausgabe

Drei Varianten: (1) manuell — Beispiel-Eingabe; (2) Jira-Trigger — startet automatisch bei angelegtem/aktualisiertem Ticket; (3) Jira→Dify-Brücke — Jira-Trigger, der die Dify-Pipeline per API aufruft.

Import in n8n

  1. n8n öffnen → Workflows → Import from File → die heruntergeladene JSON wählen.
  2. In den drei HTTP-Nodes eine Credential „HTTP Header Auth" hinterlegen (Authorization: Bearer <API-Key>).
  3. Optional Umgebungsvariablen setzen: LLM_API_URL (Standard: OpenAI-kompatibel) und LLM_MODEL (Standard: gpt-4o).
  4. Im Node „Eingabe (Beispiel)" euer Jira-Ticket einfügen (oder den Node durch einen Webhook-/Jira-Trigger ersetzen) → Execute Workflow.

Die HTTP-Nodes erwarten eine OpenAI-kompatible Chat-Completions-API (Antwortpfad choices[0].message.content). Für Anbieter mit abweichendem Format ggf. den Pfad im letzten Code-Node anpassen.

Guardrails identisch zur Dify-Pipeline: Datum aus „Erstellt", PI TBD statt erfundener Version, verlinkte Tickets nicht als Inhalt, Status/Typ wahrheitsgemäß, PII-Scrub als Netz.
